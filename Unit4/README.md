# Unit 4 — Навигация и архитектура приложения

Четвёртый юнит курса [Android Basics with Compose](https://developer.android.com/courses/android-basics-compose/course). Здесь приложения превращаются из набора экранов в **настоящую архитектуру**: у состояния появляется владелец (`ViewModel`), между экранами появляется навигация, а интерфейс учится подстраиваться под телефон, складной экран и планшет.

## Что было до этого

| Юнит | О чём |
|------|-------|
| Unit 1 | Kotlin, первые composable-функции, базовая раскладка. |
| Unit 2 | Состояние в composable (`remember`), ввод, юнит-тесты, подъём состояния. |
| Unit 3 | Списки (`LazyColumn`, `LazyVerticalGrid`), модели данных, Material 3, тема, анимации. |

Приложения Unit 3 были в основном **статичными**: данные известны заранее, экран один, состояния почти нет. Unit 4 про приложения, у которых **есть логика и несколько экранов**.

## Что нового в Unit 4

### 1. Жизненный цикл (Lifecycle)
- Activity проходит стадии `onCreate → onStart → onResume → onPause → onStop → onDestroy`.
- Состояние composable при повороте экрана **теряется**, потому что Activity пересоздаётся.
- `rememberSaveable` — сохраняет простые значения при пересоздании.
- Логи через `Log.d` и Logcat, чтобы увидеть порядок вызовов.

### 2. ViewModel и UI State
- `ViewModel` живёт дольше Activity и переживает поворот экрана.
- Состояние UI описывается отдельным классом (`GameUiState`, `CupcakeUiState`, `ReplyUiState`).
- `MutableStateFlow` внутри и `StateFlow` наружу (`asStateFlow()`), UI подписывается через `collectAsState()`.
- Поток данных **однонаправленный (UDF)**: события идут от UI к `ViewModel`, состояние — от `ViewModel` к UI.
- Фабрика `viewModel()` из `lifecycle-viewmodel-compose`.

### 3. Навигация
- `navigation-compose`: `NavHost`, `NavController`, `rememberNavController()`.
- Маршруты как строки или `enum class`, `composable(route) { ... }`.
- Передача данных между экранами и общий `ViewModel` для всего графа.
- Управление back stack: `popBackStack`, `popUpTo`, `launchSingleTop`.
- `TopAppBar` с кнопкой «назад», которая зависит от текущего экрана.
- Внешние интенты: отправка заказа через `Intent.ACTION_SEND` (шеринг).

### 4. Адаптивный интерфейс
- `WindowSizeClass` (`Compact`, `Medium`, `Expanded`) из `material3-window-size-class`.
- Одно приложение — разные раскладки: на телефоне нижняя навигация, на планшете `NavigationRail`, на большом экране постоянная панель `PermanentNavigationDrawer`.
- Паттерн **list-detail**: на широком экране список и детали рядом, на узком — по очереди.
- Определение положения складного устройства (`DevicePosture`, tabletop / book).
- `BackHandler` для корректного поведения кнопки «назад».

### 5. Архитектурные слои
- Разделение на **UI-слой** (composable + `ViewModel`) и **слой данных** (`data`, провайдеры, репозитории).
- Правило: composable не знает, откуда берутся данные, а `ViewModel` не знает ничего про Compose.

## Проекты

Все проекты лежат в `Unit4/`. Порядок — как в курсе.

### Dessert Clicker (lifecycle) — `Unit4/dessert-clicker-lifecycle`
Игра-кликер: нажимаешь на десерт, растёт счёт и продажи, десерт меняется по мере прогресса.
- Состояние хранится в composable через `rememberSaveable`.
- В `MainActivity` добавлены логи всех методов жизненного цикла.
- Кнопка «поделиться» результатом через интент.

**Чему учит:** как Activity живёт и умирает, почему состояние пропадает при повороте экрана.

### Unscramble — `Unit4/Unscramble`
Игра в слова: показывается слово с перемешанными буквами, нужно угадать. Счёт, число слов, пропуск, итоговый диалог.
- `GameViewModel`, `GameUiState`.
- `MutableStateFlow` и `collectAsState()`.
- Состояние поля ввода и ошибки также живёт во `ViewModel`.

**Чему учит:** главный паттерн всего юнита — ViewModel, UiState и однонаправленный поток данных.

### Dessert Clicker (viewmodel) — `Unit4/dessert-clicker-viewmodel`
Тот же Dessert Clicker, но состояние вынесено из composable во `ViewModel`.
- Появляется `DessertUiState`, composable больше не хранит данные сам.
- Сравнивать код с версией на `rememberSaveable`: выросла структура, но поведение стало надёжнее.

**Чему учит:** как мигрировать существующее приложение на архитектуру с ViewModel.

### Cupcake — `Unit4/Cupcake`
Заказ кексов в несколько шагов: количество, вкус, дата выдачи, итог.
- Экраны: `StartOrderScreen`, `SelectOptionScreen` (вкус и дата), `SummaryScreen`.
- Один общий `OrderViewModel` на весь граф навигации. Цена пересчитывается от выбранных опций (дополнительная плата за срочность).
- `NavHost` с маршрутами в `enum class CupcakeScreen`.
- Отправка заказа через `Intent.ACTION_SEND`.
- Отмена заказа сбрасывает `ViewModel` и возвращает на старт.

**Чему учит:** навигацию, общий ViewModel для нескольких экранов, работу с back stack, внешние интенты.

### Lunch Tray — `Unit4/Lunch-tray`
Практика: многошаговое оформление обеда — основное блюдо, гарнир, напиток, чекаут.
- Экраны выбора блюд и чекаут с общей суммой и налогом.
- `OrderViewModel` хранит выбранные позиции.
- Навигация между всеми шагами, отмена возвращает на старт.

**Чему учит:** собрать приложение в стиле Cupcake почти без подсказок.

### Reply — `Unit4/Reply`
Почтовый клиент с адаптивным UI: папки Inbox, Sent, Drafts, Spam.
- Три раскладки: `Compact` — нижняя навигация, `Medium` — `NavigationRail`, `Expanded` — постоянный drawer + list-detail.
- `ReplyViewModel`, `ReplyUiState` (текущая папка, выбранное письмо, признак «показать детали»).
- Работа с положением складного устройства, `BackHandler`.

**Чему учит:** адаптивные макеты и `WindowSizeClass`, главный навык Unit 4 для приложений под планшеты и foldable.

### Sports — `Unit4/Sports`
Практика: список видов спорта, по нажатию — подробности.
- На телефоне: список → детали, на планшете: список и детали рядом.
- Один `SportsViewModel`, один `SportsUiState`.
- Использует `WindowSizeClass`, как Reply, но без навигационной панели.

**Чему учит:** list-detail самостоятельно.

### My City — `Unit4/My-city`
Итоговое приложение юнита: гид по выбранному городу. Категории мест (кафе, парки, музеи и т.д.), список, детали.
- Свой список из 24 мест Казани с описаниями и адресами (вместо фото — иконки на градиенте): `LocalPlacesDataProvider`, модель `Place`. Подробности в `Unit4/My-city/README.md`.
- `CityViewModel`, `NavHost`, адаптивная раскладка.
- Своя тема, свои иконки.

**Чему учит:** объединить всё из курса — списки, тему, ViewModel, навигацию, адаптивность — в одном приложении без готовых шаблонов.

## Какие проекты похожи друг на друга

| Пара / группа | Что общего | Чем отличаются |
|---------------|-----------|----------------|
| **Dessert Clicker (lifecycle) ↔ Dessert Clicker (viewmodel)** | Это **одно и то же приложение**: тот же интерфейс, те же десерты, та же логика. | В lifecycle состояние живёт в composable через `rememberSaveable`, в viewmodel вынесено в `ViewModel` с `DessertUiState`. Сделаны специально для сравнения двух подходов. |
| **Dessert Clicker (viewmodel) ↔ Unscramble** | Одинаковый паттерн: `ViewModel` + `UiState` + `StateFlow` + `collectAsState()`. | Unscramble написан с нуля как основной пример этого паттерна, в нём больше логики: игровой цикл, ввод, проверка ответа. Dessert Clicker показывает перенос существующего кода. |
| **Cupcake ↔ Lunch Tray** | Одна схема: многошаговый заказ, `NavHost`, один общий `OrderViewModel` на весь граф, итоговый экран, отмена со сбросом. Lunch Tray — это Cupcake для самостоятельной работы. | Cupcake: количество, вкус, дата, интент для отправки заказа. Lunch Tray: блюдо, гарнир, напиток, чекаут с налогом, без интентов. |
| **Reply ↔ Sports** | Оба показывают паттерн **list-detail** и используют `WindowSizeClass` с одним `ViewModel` и `UiState`. Sports — упрощённая версия Reply. | Reply: три раскладки (нижняя навигация, rail, drawer), папки, складные устройства. Sports: только список и детали, без навигационной панели. |
| **My City** | Собирает всё сразу: список как в Reply и Sports, `NavHost` как в Cupcake, `ViewModel` как в Unscramble, тема как в Unit 3. | Свой набор данных и дизайн: нет готового шаблона. |

Если смотреть кратко, то уникальных идей в юните четыре, и каждая закрепляется вторым проектом:

1. **ViewModel и состояние:** Unscramble → Dessert Clicker (viewmodel).
2. **Навигация:** Cupcake → Lunch Tray.
3. **Адаптивность:** Reply → Sports.
4. **Всё вместе:** My City.

Dessert Clicker (lifecycle) стоит особняком: это не архитектура, а демонстрация проблемы, которую потом решает `ViewModel`.

## Что нового по сравнению с Unit 1–3

| Тема | Unit 1–3 | Unit 4 |
|------|----------|--------|
| Где живёт состояние | В composable (`remember`) | Во `ViewModel` (`StateFlow`) |
| Поворот экрана | Состояние теряется или не замечаем | Состояние сохраняется |
| Число экранов | Один | Несколько, `NavHost` |
| Размер экрана | Телефон | Телефон, планшет, складной |
| Архитектура | Всё в одном месте | UI-слой + слой данных |
| Поток данных | Произвольный | Однонаправленный (UDF) |
| Внешние действия | Нет | Интенты (шеринг) |
| Зависимости | Compose, Material 3 | + `navigation-compose`, `lifecycle-viewmodel-compose`, `window-size-class` |

## Что за пределами курса
Данные в Unit 4 по-прежнему хранятся в памяти или в коде. Сети (Retrofit), базы данных (Room), DataStore и Hilt — это уже следующие юниты курса.
